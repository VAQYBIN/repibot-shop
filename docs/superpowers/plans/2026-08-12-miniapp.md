# MiniApp: мобильное приложение вместо уменьшенного сайта

> **Для исполнителя:** план выполняется задача за задачей. Шаги помечены `- [ ]`.

**Цель:** заменить строку ссылок нижней панелью вкладок, отдать главное действие каждого экрана кнопке Телеграма и привести семь экранов к плотной шкале.

**Устройство:** обёртка над Telegram WebApp дополняется поддержкой `MainButton` и отклика вибрацией; поверх неё появляется хук, который сам снимает обработчик при уходе с экрана. Дальше — нижняя панель вкладок в корневом маршруте и семь экранов. Веб-приложение в этом плане не трогается вовсе.

**Стек:** React 19, TanStack Router, Vite, Tailwind 4, vitest, Telegram Bot API 8.

## Общие ограничения

- **Ветка `dev`.** Никаких git-команд: коммиты делает ведущий после проверки задачи.
- **Только `frontend/apps/miniapp`.** Весь `apps/web` и весь `packages` — чужие: там одновременно работают четыре других плана.
- **Никакого прогона проверок по всему репозиторию.** Только свои тесты: `pnpm --filter @repibot/miniapp test <файл>`.
- **Существующие тесты — договор.** Покрыты шесть маршрутов из семи. Обязаны остаться зелёными; упавший тест — повод сначала доказать, что поведение изменилось намеренно.
- **Адреса маршрутов не меняются.** Ни один из семи. Панель вкладок показывает пять из них, но `/support` и `/winback` остаются рабочими адресами — на них приходят по ссылкам из бота.
- **Кегли — только по шкале бренда:** `text-display`, `text-h1`, `text-h2`, `text-h3`, `text-body`, `text-small`, `text-caption`. Встроенные погашены и молча не работают.
- **Цвета — только токенами.** Палитра остаётся наша: MiniApp узнаётся как Re:Pibot, а не растворяется в теме клиента.
- **Иконки — через `Icon` из `@repibot/ui`.** Имена сверять по `node_modules/@hugeicons/core-free-icons/dist/index.d.ts`.
- **Новых ключей словаря не заводить.** Всё нужное уже добавлено в оба словаря ведущим: `miniapp.tab.home`, `miniapp.tab.subscription`, `miniapp.tab.devices`, `miniapp.tab.payments`, `miniapp.tab.profile` и `miniapp.nav.label` — название самой панели для скринридера.
- **Комментарии по-русски и о том, почему.** Никаких `// biome-ignore` без сработавшего правила.

```ts
export interface MainButtonState {
  text: string
  visible: boolean
  loading: boolean
  disabled: boolean
}

/** Есть ли в клиенте главная кнопка. В старых клиентах её нет. */
export function hasMainButton(): boolean

/** Применяет состояние к кнопке. Обработчик ставится отдельно. */
```

```ts
interface TelegramMainButton {
  setText: (text: string) => void
  show: () => void
  hide: () => void
  enable: () => void
  disable: () => void
  showProgress: (leaveActive?: boolean) => void
  hideProgress: () => void
  onClick: (handler: () => void) => void
  offClick: (handler: () => void) => void
}

interface TelegramHaptics {
  notificationOccurred: (type: 'error' | 'success' | 'warning') => void
  impactOccurred: (style: 'light' | 'medium' | 'heavy' | 'rigid' | 'soft') => void
}
```

и поля `MainButton?: TelegramMainButton`, `HapticFeedback?: TelegramHaptics`.

Дальше — сами функции. Все они молча ничего не делают, если Телеграма нет: MiniApp открывается и в обычном браузере при разработке, и падение там означало бы белый экран вместо приложения.

```ts
export function hasMainButton(): boolean {
  return webApp()?.MainButton !== undefined
}

export function applyMainButton(state: MainButtonState): void {
  const button = webApp()?.MainButton
  if (button === undefined) return
  button.setText(state.text)
  if (state.loading) button.showProgress(true)
  else button.hideProgress()
  if (state.disabled || state.loading) button.disable()
  else button.enable()
  if (state.visible) button.show()
  else button.hide()
}
```

`haptic` переводит наши три случая в понятия Телеграма: `success` и `error` — уведомления, `tap` — лёгкий удар.

### Задача 2: Хук главной кнопки

**Файлы:**

- Отдаёт:

```ts

  text: string
```

Хук обязан снимать обработчик при уходе с экрана. Иначе кнопка предыдущего экрана нажимается на следующем: у Телеграма кнопка одна на всё приложение, и она переживает смену маршрута.

```tsx
const offClick = vi.fn()
vi.mock('./telegram', () => ({
  hasMainButton: () => true,
  applyMainButton: vi.fn(),
  hideMainButton: vi.fn(),
  onMainButtonClick: (handler: () => void) => {
    void handler
    return offClick
  },
}))

function Screen() {
  useMainButton({ text: 'Купить', onClick: () => undefined })
  return <p>экран</p>
}

describe('useMainButton', () => {
  it('снимает обработчик при уходе с экрана', () => {
    /* Кнопка у Телеграма одна на всё приложение и переживает смену
       маршрута: неснятый обработчик сработает на следующем экране. */

    view.unmount()

    expect(offClick).toHaveBeenCalled()
  })
})
```

- [ ] **Шаг 3: Написать хук**

Обработчик держать в `useRef` и ставить в `onMainButtonClick` один раз: если передавать его напрямую, каждая перерисовка снимала бы и ставила обработчик заново, а вместе с этим мигала бы сама кнопка.

Состояние применять в отдельном `useEffect`, зависящем от текста и признаков. При размонтировании — снять обработчик и спрятать кнопку.
