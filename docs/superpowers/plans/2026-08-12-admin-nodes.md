# Ноды в админке — план реализации

> **Для исполнителей:** задачи выполняются по одной, каждая заканчивается зелёными тестами. Шаги отмечены галочками (`- [ ]`).

**Цель:** показать администратору состояние узлов панели — только просмотр.

**Устройство:** панель отдаёт `GET /api/nodes`; в нашей интеграции нод нет, поэтому появляются корневая схема в генераторе моделей, фасад `PanelNodes` рядом с `PanelSquads` и маршрут, переводящий ответ панели в нашу схему. Молчащая панель не роняет страницу.

**Основание:** `docs/superpowers/specs/2026-08-12-admin-console-design.md`, раздел 4.

**Стек:** Python 3.13, httpx, FastAPI, pytest; React 19, Next.js 16, TanStack Query, Vitest.

**Предшествует:** план каркаса (`2026-08-12-admin-shell.md`).

## Общие ограничения

- Комментарии и строки документации по-русски, объясняют **почему**.
- TDD: тест пишется первым и обязан упасть по названной причине.
- mypy strict, ruff line-length 100, окончания строк LF.
- Админка живёт без переводов — русский прямо в разметке.
- **Агент не выполняет команд git**, не запускает `uv run check` целиком, не форматирует пакет целиком и **не перегенерирует клиент OpenAPI нашего API** — это делает ведущий.
- Модели **панели** перегенерировать нужно, и это часть задачи 1 — не путать с клиентом нашего API.
- `# noqa: BLE001` не нужен; `# type: ignore` наугад не ставить.

### Задача 1: Модели и фасад нод

**Файлы:**
- Изменить: `tools/gen_remnawave_models.py` (корневая схема)
- Изменить: `backend/core/src/repibot_core/integrations/remnawave/models.py` (перегенерация, руками не править)
- Изменить: `backend/core/src/repibot_core/integrations/remnawave/types.py` (псевдонимы)
- Создать: `backend/core/src/repibot_core/integrations/remnawave/nodes.py`
- Тест: `backend/core/tests/test_remnawave_nodes.py`, `backend/core/tests/test_remnawave_types.py` (дописать)

**Отдаёт:**

```python
class PanelNodes:
    def __init__(self, client: RemnawaveClient) -> None: ...
    async def list(self) -> list[PanelNode]: ...
```

**Главный риск задачи.** Генератор называет вложенные безымянные объекты по порядку — `Response`, `Response1`, `Status2`. Добавление корневой схемы **сдвигает номера**, и `types.py` начинает указывать не туда. Файл `types.py` для того и написан: правится он, а не весь код. Об этом прямо сказано в его строке документации, и `test_remnawave_types` ловит расхождение.

Порядок действий поэтому строгий: сначала добавить схему и перегенерировать, затем прогнать `test_remnawave_types`, затем **починить псевдонимы**, и только потом писать фасад. Если начать с фасада, падение придёт из чужого кода и будет выглядеть необъяснимым.

- [ ] **Шаг 1: Добавить корневую схему**

В `tools/gen_remnawave_models.py`, в `ROOT_SCHEMAS`, добавить `"GetNodesResponseDto"` — список отсортирован по алфавиту, место соответствующее.

- [ ] **Шаг 2: Перегенерировать модели панели**

Команду взять из `tools/gen_remnawave_models.py` (модуль исполняемый) или из документации разработчика. Файл `models.py` — вывод генератора; править его руками нельзя.

- [ ] **Шаг 3: Прогнать проверку псевдонимов**

```
uv run pytest backend/core/tests/test_remnawave_types.py backend/core/tests/test_remnawave_models_generation.py -q
```
Ожидание: **падение** на съехавших псевдонимах — это ожидаемое следствие шага 1, а не ошибка. Если тест зелёный, номера не сдвинулись, и чинить нечего.

- [ ] **Шаг 4: Починить псевдонимы**

В `types.py` привести `PanelUser`, `PanelUsage`, `PanelStatus` и прочие к новым номерам и добавить `PanelNode`. Комментарий над блоком уже объясняет, почему номера меняются, — дополнить его упоминанием нод, чтобы следующий читатель знал, от чего сдвинулось в этот раз.

- [ ] **Шаг 5: Тест на разбор ответа панели**

`backend/core/tests/test_remnawave_nodes.py`, образец устройства теста — `test_remnawave_facades.py` и `test_support_chat.py` (`httpx.MockTransport`):

```python

    протокола, и знать о ней должен только фасад."""
```

- [ ] **Шаг 6: Тест на отказ панели**

Ожидание: `RemnawaveRejected`.

### Задача 2: Маршрут нод

**Файлы:**
- Создать: `backend/api/src/repibot_api/routers/admin/nodes.py`
- Изменить: `backend/api/src/repibot_api/routers/admin/__init__.py` (включить подроутер)
- Схема ответа объявляется **в самом модуле маршрута**, а не в общем `schemas.py`: соседние планы наполняют пакет админки одновременно, и общий файл стал бы местом столкновения. Прецедент — `WhoAmIResponse` в корне пакета.
- Тест: `backend/api/tests/test_admin_nodes.py`

**Маршрут:** `GET /api/admin/nodes`, роль `admin`.

Наружу отдаём только то, что показываем: имя, страну, адрес с портом, связь, включена ли, людей онлайн, потраченный трафик и лимит, время работы Xray, последнее сообщение о состоянии. Пробрасывать ответ панели целиком нельзя — там секреты узла и внутренние идентификаторы, которым в браузере администратора делать нечего.
