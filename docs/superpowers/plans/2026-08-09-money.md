# Подпроект 3 «Деньги» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить надёжные ручные покупки YooKassa и Telegram Stars, промокоды,
подарки, реферальные дни, автопродление и уведомления без двойной выдачи
доступа или повторного списания.

**Architecture:** Коммерческий заказ — неизменяемый снимок тарифа и цены;
конкретное обращение к провайдеру хранится отдельной попыткой оплаты. Единый
идемпотентный финализатор в одной транзакции меняет заказ и entitlement,
погашает промокод, выдаёт ваучер или реферальные дни и записывает outbox.
YooKassa, Telegram, Remnawave и SMTP вызываются только после commit.

**Tech Stack:** Python 3.13, FastAPI, SQLAlchemy 2 async/PostgreSQL, Alembic,
httpx, TaskIQ/Valkey, aiogram 3, YooKassa HTTP API, React 19, Next.js 16,
TanStack Query v5, TanStack Router, Vitest, Playwright.

## Global Constraints

- Использовать `Decimal`/Postgres `NUMERIC(10,2)` для рублей, не `float`.
- Цена и длительность приходят только из серверного снимка активного тарифа;
  клиент передаёт только `plan_id`, purpose, provider и необязательный код.
- Ровно один промокод на ручной `purchase`/`renew`; он не применим к gift и
  auto-renew. YooKassa заказ живёт 30 минут, Stars — 15 минут.
- Заказ и provider attempt имеют уникальные ключи идемпотентности; финализатор
  берёт блокировки в порядке order → subscription → promo/voucher/referral.
- Подарок — обычный тариф, оплаченный с `purpose=gift`; ваучер одноразовый.
- Реферальная награда: `max(1, floor(purchased_days * percent / 100))`,
  режим `first|every` и процент читаются из `.env`; денежного баланса,
  списаний баланса и выплат нет.
- Автопродление YooKassa делает три попытки: -24h, +6h, +12h; успех и каждая
  неудача уведомляются в Telegram и на подтверждённый email, если доступны.
- Ручной возврат в YooKassa только фиксируется в системе; отзыв дней и
  реферальной награды — отдельная аудируемая компенсация администратора.
- Любой новый API экспортируется в OpenAPI и затем в
  `frontend/packages/core/src/api/schema.d.ts` через `uv run verify-generated`.
- Каждая задача: сначала RED, затем минимальный GREEN, focused tests,
  self-review, один тематический commit. Полный `uv run check` запускается
  перед каждым крупным интеграционным commit и перед финальной сдачей.

## Plan Self-Review

- **Coverage:** Tasks 1–2 establish snapshots, locking and transaction-neutral
  entitlement; 3–5 add both providers and manual flow; 6–8 cover promos,
  gifts, referrals, returns, notifications and auto-renew; 9–10 expose client
  contracts; Task 11 covers admin, E2E and release documentation.
- **Consistency:** `Order`/`PaymentAttempt` are the only provider-facing
  aggregates in every task. `PaymentService.finalize_success()` is the sole
  success path for YooKassa, Stars, polling and retries. No task recreates a
  money balance or payout scope excluded by the approved spec.
- **Safety:** every external confirmation is verified, every irreversible
  effect has a unique origin, and no external network call is placed inside a
  DB transaction.
- **No placeholders:** exact files, interfaces, failing tests, verification
  commands and commit boundaries are present for each task.
