# Подпроект 7 — Витрина

Дата: 2026-08-12
Статус: утверждён
Область: продающий лендинг, юридические документы, публичная оболочка сайта,
подмена лендинга своим при развёртывании.

---

## 1. Что строим

Подпроекты 0–6 закрыли всё, что происходит после того, как человек вошёл.
До входа его встречает карточка «Магазин ещё готовится», а ссылки на
юридические документы ведут на страницу-заглушку: таблицы `legal_documents`
из архитектуры не существует — ни модели, ни миграции, ни API.

Подпроект закрывает обе дыры и добавляет третью возможность, которой в
архитектуре не было: развернувший проект у себя может подменить лендинг
своим, не пересобирая образы.

Функциональность за пределами публичной части не меняется. Контракт
существующих эндпоинтов остаётся прежним, новые только добавляются.

## 2. Принятые решения

| Решение | Выбор | Причина |
|---|---|---|
| Набор документов | Задаёт админ, произвольные slug'и | Проект открытый: у каждого своё юрлицо и свой перечень |
| Заготовки текстов в репозитории | Нет | Заготовка требует заранее известного имени, а набор произвольный. Чужая оферта хуже, чем её отсутствие |
| Хранение документа | Markdown, как его набрал админ | Правится руками; HTML на его месте лишил бы админа этой возможности |
| Отрисовка Markdown | На бэкенде, публичный API отдаёт готовый HTML | Одна очистка вместо двух, фронт без парсера в бандле |
| Ссылка на Telegra.ph | Способ ввода, а не источник | Пост удалят или сервис ляжет — оферта останется на месте |
| Разрешённые адреса импорта | Только `telegra.ph` | Эндпоинт, ходящий по произвольному URL, простукивает внутреннюю сеть снаружи |
| Версии документа | Строка неизменяема, правка создаёт новую | На спор «я покупал на других условиях» отвечает история, а не память |
| Доступ к документам | Роль `admin` | `support` не допущен к тарифам — юридические тексты не мягче |
| Тарифы на лендинге | Живые, из `GET /api/plans` | Переписанная руками цена расходится с настоящей в первый же день |
| Рендеринг лендинга | На сервере | Иначе поисковику и превью ссылки достаётся пустая страница |
| Содержание доводов | Только проверяемое по коду | За «военное шифрование» и «сто стран» потом краснеть |
| Подмена лендинга | В nginx, каталогом только для чтения | Не требует ни Node, ни пересборки образа, ни переключателя в настройках |
| Документов нет | О них нигде не говорится | Пустой раздел «Правовая информация» без ссылок хуже его отсутствия |

## 3. Юридические документы

### 3.1 Модель

Таблица `legal_documents` из архитектуры плюс одно поле — `title`. Без него
нечем подписать ссылку в подвале, а вытаскивать заголовок из первой строки
Markdown — гадание на чужом тексте.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `int` | Первичный ключ |
| `slug` | `str(64)` | Имя в адресе: `/legal/<slug>`. Задаёт админ |
| `locale` | `str(2)` | `ru` или `en` |
| `title` | `str(200)` | Заголовок: подпись ссылки и `<h1>` страницы |
| `content` | `text` | Markdown, как его набрал админ |
| `version` | `int` | Номер версии в пределах пары `slug` + `locale`, с единицы |
| `published_at` | `datetime \| None` | Пусто — черновик |
| `created_by_id` | `int \| None` | Кто создал версию |
| `created_at`, `updated_at` | `datetime` | Из `TimestampMixin` |

Ограничения: уникальность `(slug, locale, version)`; частичный уникальный
индекс `(slug, locale) where published_at is null` — черновик у пары ровно
один; индекс `(slug, locale, version desc)` для выборки последней версии.

`slug` проверяется по `^[a-z0-9-]{2,64}$`. Иначе имя документа окажется
частью пути с косой чертой внутри.

### 3.2 Версии

Опубликованная строка неизменяема. Правка создаёт черновик с
`version = max(version) + 1`, публикация проставляет ему `published_at`.
Публичная страница показывает наибольшую опубликованную версию.

Отката одной кнопкой нет: чтобы вернуть старый текст, админ открывает нужную
версию и публикует её заново — получается новая версия с прежним
содержимым. История при этом остаётся линейной, и вопрос «какой текст
действовал в марте» имеет ровно один ответ.

### 3.3 Markdown и HTML

Хранится Markdown. Публичный API отдаёт HTML, собранный из него на бэкенде
и пропущенный через очистку.

- Разбор — `markdown-it-py` в режиме CommonMark, без плагинов и без
  `html=True`: сырой HTML внутри Markdown не разбирается, а экранируется.
- Очистка — `nh3`. Разрешены: `p`, `h2`–`h4`, `ul`, `ol`, `li`, `strong`,
  `em`, `a`, `blockquote`, `code`, `pre`, `hr`, `br`, `table`, `thead`,
  `tbody`, `tr`, `th`, `td`. У `a` разрешён `href` со схемами `http`,
  `https`, `mailto`; ко всем внешним ссылкам добавляется
  `rel="nofollow noopener"` и `target="_blank"`.
- `h1` в разрешённые не входит: заголовок страницы берётся из `title`, и
  второй `h1` в тексте ломал бы структуру документа.

Очистка выполняется при отдаче, а не при сохранении. Список разрешённого со
временем меняется, и документы, сохранённые по старым правилам, не должны
оставаться с дырой внутри.

### 3.4 Импорт с Telegra.ph

`POST /api/admin/legal/import` принимает `{"url": "..."}` и возвращает
`{"title": "...", "content": "..."}`. Ничего не сохраняет: админ видит текст
в редакторе, правит и публикует сам.

Порядок работы: из адреса берётся путь, выполняется запрос
`GET https://api.telegra.ph/getPage?path=<path>&return_content=true`, узловое
дерево ответа переводится в Markdown.

Соответствие узлов: `p` — абзац, `h3`/`h4` — `##`/`###`, `ul`/`ol`/`li` —
списки, `b`/`strong` — `**`, `i`/`em` — `*`, `a` — ссылка, `code` — обратные
кавычки, `pre` — блок кода, `blockquote` — `>`, `hr` — `---`, `br` — перенос
строки. Узлы `img`, `video`, `iframe`, `figure` отбрасываются с их
содержимым: юридический документ с картинкой нам не нужен, а тянуть
чужие файлы к себе — отдельная история про хранилище.

Ошибки: адрес не с `telegra.ph` (`400 invalid_source`), страница не найдена
(`404 not_found`), сервис недоступен или ответил не за пять секунд
(`502 import_failed`). Ходить по произвольным адресам эндпоинт не умеет —
хост проверяется точным сравнением с `telegra.ph` и `api.telegra.ph` после
разбора URL, а не поиском подстроки.

### 3.5 Публичный API

`GET /api/legal?locale=ru` — список опубликованных документов:
`[{"slug": "...", "title": "...", "published_at": "..."}]`. По одному на
slug.

`GET /api/legal/{slug}?locale=ru` — документ:
`{"slug", "title", "html", "locale", "version", "published_at"}`.

Локаль выбирается так: запрошенная, если для неё есть опубликованная
версия; иначе любая другая, где она есть, с русской в приоритете. Отданная
локаль всегда возвращается в ответе. Это нужно, чтобы подвал на английском
не приводил в 404, когда админ завёл только русский текст.

Черновики публично не видны никогда. Документ без единой опубликованной
версии для запроса `GET /api/legal/{slug}` не существует — `404`.

В отличие от тарифов, где `name` отдаётся сразу всеми локалями, документ
отдаётся одной: два полных текста в одном ответе — лишние килобайты на
каждой загрузке страницы.

### 3.6 Админский API и экран

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/admin/legal` | Документы с черновиками и датами публикации |
| `GET` | `/api/admin/legal/{slug}/{locale}` | Черновик или последняя версия, Markdown |
| `GET` | `/api/admin/legal/{slug}/{locale}/versions` | История: номер, дата, автор |
| `GET` | `/api/admin/legal/{slug}/{locale}/versions/{version}` | Текст конкретной версии |
| `PUT` | `/api/admin/legal/{slug}/{locale}` | Сохранить черновик |
| `POST` | `/api/admin/legal/{slug}/{locale}/publish` | Опубликовать черновик |
| `DELETE` | `/api/admin/legal/{slug}/{locale}` | Снять с публикации |
| `POST` | `/api/admin/legal/import` | Импорт с Telegra.ph |

Все — под `require_role(admin)`. Публикация и снятие пишутся в `audit_log` с
состоянием до и после.

Снятие с публикации не стирает версии. Документ пропадает из подвала и с
публичного API, но история остаётся: удалить текст, на условиях которого
кто-то уже купил, — ровно то, ради чего версии и заводились. Физически
строки удаляет только миграция или админ базы, и это осознанно не наша
кнопка.

Экран `/admin/legal`: список документов, у каждого — slug, заголовок, локаль,
номер опубликованной версии и отметка о несохранённом черновике. Внутри —
поле Markdown, поле заголовка, кнопка загрузки с Telegra.ph, предпросмотр
готового HTML и список версий. Компоновка следует остальной админке:
`AdminPage` с заголовком и действиями справа.

## 4. Лендинг

### 4.1 Блоки

Сверху вниз: шапка, первый экран, доводы, «как это работает», тарифы,
частые вопросы, подвал.

**Первый экран.** Знак, обещание, поясняющая строка, две кнопки. Первая
кнопка зависит от данных: если среди тарифов есть активный триальный
(`is_trial`), это «Попробовать бесплатно» со ссылкой на регистрацию; если
триал выключен — «Выбрать тариф». Лендинг не обещает того, чего в системе
нет, и это главная причина брать тарифы живыми, а не текстом.

**Доводы** — четыре, каждый заголовком и строкой пояснения.

**«Как это работает»** — три шага с номерами.

**Тарифы** — карточки из `GET /api/plans` тем же компонентом `PlanCard`, что
и на `/plans`. Ниже — ссылка на полный список.

**Частые вопросы** — шесть пар, раскрывающихся по нажатию.

### 4.2 Тексты

Русские тексты фиксируются здесь, английские — перевод при реализации. Все
живут ключами `landing.*` в `packages/core/src/i18n`.

Обещание: **«Подписка на доступ. Одна ссылка — все устройства.»**
Пояснение: «Выберите тариф, оплатите картой или звёздами и откройте ссылку
в приложении. Пробный период — без карты.»

Доводы:

1. **Пробный период без карты.** Привяжите Telegram и получите доступ на
   пробу. Платёжные данные для этого не нужны.
2. **Одна ссылка на все устройства.** Подписка выдаётся ссылкой, она не
   меняется при продлении. Сколько устройств можно подключить — написано в
   тарифе, лишнее отвязывается в кабинете.
3. **Оплата картой или звёздами.** YooKassa и Telegram Stars. Карта
   запоминается, только если вы сами отметите это на странице оплаты.
4. **Поддержка отвечает туда, где спросили.** Напишите из кабинета или боту:
   ответ придёт в ту же переписку и в уведомления.

Шаги:

1. **Создайте аккаунт** — почтой, ключом доступа или через Telegram.
2. **Выберите тариф** — оплатите картой или звёздами. Для пробного периода
   платить не нужно.
3. **Подключитесь** — скопируйте ссылку подписки в кабинете и откройте её в
   своём приложении.

Частые вопросы:

1. **Что будет с оплаченными днями, если сменить тариф?** Остаток не
   сгорает. Он пересчитывается по стоимости дня текущего тарифа и
   превращается в дни нового; неполный день отбрасывается.
2. **Как отключить автопродление?** Отвяжите карту в кабинете — списывать
   станет нечем, и автопродление выключится.
3. **Где взять ссылку подключения?** В кабинете и в MiniApp, раздел
   «Подписка». Ссылка одна и остаётся прежней после продления.
4. **Сколько устройств можно подключить?** Столько, сколько указано в
   тарифе. Список подключённых виден в кабинете, любое можно отвязать.
5. **Зачем для пробного периода нужен Telegram?** Пробный период даётся один
   раз на аккаунт Telegram. Почтовый адрес завести проще, чем аккаунт,
   поэтому считаем по нему.
6. **Храните ли вы данные карты?** Нет. Оплата проходит на стороне YooKassa,
   нам возвращается только идентификатор способа оплаты и маска номера,
   чтобы вы понимали, какая карта привязана.

Каждое утверждение проверено по коду: пересчёт — `domain/subscriptions.py`,
`convert_remainder`; ссылка подписки — `remnawave_short_uuid`; лимит
устройств — `hwid_device_limit` тарифа; пробный период — `trial_grants` по
`telegram_id`; способы оплаты — `payments.provider`.

### 4.3 Рендеринг

Лендинг — серверный компонент. Тарифы забираются на сервере, чтобы цены
попали в HTML: клиентская загрузка оставила бы поисковику и превью ссылки
пустую страницу.

Список правовых ссылок берётся иначе — клиентским запросом внутри подвала,
одинаково на всех страницах. Заводить для него второй, серверный путь
получения незачем: в подвале он не нужен поисковику, а один способ вместо
двух означает один набор состояний загрузки и ошибки.

Для серверного запроса нужен внутренний адрес API — переменная
`INTERNAL_API_URL` со значением по умолчанию `http://api:8000`.
Относительный путь, которым пользуется браузер, на сервере не разрешается.
Переменная объявляется в `compose.yml` у сервиса `web` и в `.env.example`.

Ответ API кэшируется на 60 секунд (`next.revalidate`): цена тарифа меняется
раз в месяц, а главную открывают чаще.

Если API не ответил или ответил ошибкой, страница всё равно отдаётся: блок
тарифов заменяется ссылкой «Смотреть тарифы» на `/plans`, колонка правовых
ссылок в подвале не появляется. Пятисотка на главной из-за недоступного
бэкенда недопустима — лендинг обязан работать, даже когда магазин временно
не работает.

Язык остаётся как во всём вебе: первый кадр русский, после гидратации
подставляется язык браузера. Индексируется русская версия.

## 5. Публичная оболочка

Общие шапка и подвал появляются на `/`, `/plans` и `/legal/*`.

**Шапка**: горизонтальный лок-ап со ссылкой на главную, ссылки «Тарифы» и
«Поддержка», переключатель темы, кнопка «Войти». На узком экране ссылки
сворачиваются, лок-ап и кнопка остаются.

**Подвал**: лок-ап, короткая строка о проекте, колонка ссылок раздела
(«Тарифы», «Вход», «Регистрация»), колонка правовых ссылок из
`GET /api/legal`, строка с годом. Если документов нет, колонки правовых
ссылок нет вовсе — вместе с заголовком.

**Вход и регистрация** сохраняют центрированную компоновку. Под кнопкой
регистрации появляется строка «Продолжая, вы принимаете …» со ссылками на
заведённые документы — и только если они заведены. Отдельной галочки нет:
согласие выражается действием, а обязательная галочка добавляет шаг, не
добавляя доказательства.

**Открытая графика и индексирование.** В `layout.tsx` добавляются
`openGraph` и `twitter` с картинкой `og-image.png`; растр копируется из
брендового набора в `public`, а существующий тест соответствия копий
дополняется его именем. Появляются `robots.txt` и `sitemap.xml` маршрутами
Next: в карту сайта входят `/`, `/plans` и опубликованные документы;
`/account`, `/admin` и страницы входа исключены. Список документов для карты
сайта берётся на сервере, тем же внутренним адресом, что и тарифы; при
недоступном API карта отдаётся с одними статическими адресами.

## 6. Свой лендинг

Последняя задача подпроекта — возможность подменить главную своей страницей.

### 6.1 Как устроено

Каталог монтируется в контейнер nginx только для чтения по пути
`/srv/landing`. Корневая локация сначала пробует отдать из него
`index.html` и лишь потом уходит в приложение:

```nginx
location = / {
    root /srv/landing;
    try_files /index.html @web;
    include /etc/nginx/snippets/security-headers.conf;
}

location /landing/ {
    alias /srv/landing/;
    include /etc/nginx/snippets/security-headers.conf;
}

location @web {
    set $web_upstream http://web:3000;
    proxy_pass $web_upstream$request_uri;
    ...
}
```

В `compose.yml` у сервиса `nginx` появляется том:

```yaml
volumes:
  - ${LANDING_DIR:-./landing}:/srv/landing:ro
```

Пустой каталог означает штатный лендинг. Переключателя «включить своё» нет:
наличие файла и есть переключатель.

Политики содержимого у веб-локации нет (в отличие от MiniApp), поэтому
чужая страница со своими стилями и скриптами работает без послаблений в
конфигурации.

### 6.2 Что документируется

Раздел в `docs/deployment.md` описывает:

- куда класть файлы, как выглядит том в `compose.yml`, чем перезапускать;
- обязательные адреса на странице: `/register`, `/login`, `/plans` и
  `/legal/<slug>` для заведённых документов. Без первых двух купить нельзя,
  без последнего эквайринг не подключат;
- как получить данные для своей страницы прямо из браузера:
  `GET /api/plans` и `GET /api/legal` открыты без входа, поэтому цены и
  правовые ссылки не обязаны быть переписанными руками;
- где лежат ассеты и по какому адресу они доступны (`/landing/…`);
- какие адреса занимать нельзя: `/api`, `/app`, `/webhook`, `/health` и
  любые пути приложения;
- знак и цвета из бренд-бука со ссылкой на `docs/design/logo`;
- как вернуть штатный лендинг: убрать `index.html` и перезапустить nginx.

## 7. Тестирование

| Уровень | Что проверяется |
|---|---|
| pytest, домен | Отрисовка Markdown; очистка HTML на враждебных входах: `<script>` в тексте, `javascript:` в ссылке, `onerror` в атрибуте, сырой HTML внутри Markdown |
| pytest, импорт | Перевод узлового дерева Telegra.ph в Markdown; отброс картинок; адрес не с telegra.ph; страница не найдена; сервис не ответил |
| pytest, сервис | Версии: правка создаёт новую, публикация проставляет дату, откат публикацией старой версии; черновик у пары один |
| pytest, роутеры | Черновик публично не виден; `support` не допущен; выбор локали и запасной вариант; `404` на документ без публикаций; запись в `audit_log` |
| vitest | Подвал без документов не рисует колонку; первая кнопка меняется при отсутствии триала; блок тарифов при недоступном API заменяется ссылкой; страница документа рисует HTML |
| Playwright | Главная и страница документа входят в сквозной обход тридцати с лишним экранов в обеих темах; отдельный прогон пересоздаёт nginx с пробным каталогом и проверяет, что `/` отдаёт чужую страницу, а `/plans`, `/login` и `/api/plans` продолжают работать |

Проверка чужого лендинга возвращает контур в исходное состояние после
прогона — иначе следующий запуск сквозного обхода увидит вместо главной
пробную страницу и не объяснит, почему.

## 8. Как реализуется

Внешний вид делается скиллами `impeccable`, `frontend-design` и
`design-taste-frontend`; источник готовых решений — MCP 21st.dev.
Дизайн-система подпроекта 6 — рамка: шкала кеглей, плотность, цвета и
компоненты `packages/ui` остаются, лендинг не заводит своих. Бренд-бук
остаётся рамкой для знака и цвета.

## 9. Чего осознанно не делаем

- **Визуального редактора документов.** Markdown с предпросмотром покрывает
  оферту; WYSIWYG — отдельный проект со своей историей багов.
- **Отката версии одной кнопкой.** Публикация старой версии заново делает
  то же и не заводит второй способ менять историю.
- **Перевода документов силами системы.** Русский и английский админ заводит
  отдельно. Машинный перевод юридического текста — способ подписаться под
  тем, чего не читал.
- **Блога, новостей, статусной страницы.**
- **Счётчиков, аналитики, пикселей.** Открытый проект не должен по умолчанию
  отправлять посетителей третьей стороне.
- **Отзывов, логотипов «нам доверяют», счётчиков пользователей.** Всё это
  пришлось бы либо выдумать, либо поддерживать вручную.
- **Своей страницы для MiniApp и кабинета.** Подменяется только `/`.
