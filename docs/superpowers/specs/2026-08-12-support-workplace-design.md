# Рабочее место поддержки: спецификация

**Дата:** 2026-08-12
**Основание:** проверка поддержки на живом стенде после подпроекта 4
**Область:** супергруппа поддержки, обращения, блокировка пользователя

## Задача

Поддержка работает: обращение доходит до темы супергруппы, ответ сотрудника
доходит до человека. Но сама тема — голая. Сотрудник видит текст вопроса и
больше ничего: ни кто спрашивает, ни что у него с подпиской, ни какие
обращения ещё ждут ответа. Единственная команда `/close` есть, но о ней
нигде не написано, поэтому её всё равно что нет.

Спецификация превращает тему из ленты сообщений в рабочее место: состояние
видно из списка тем, собеседник — из первого сообщения, а управление
обращением помещается в семь команд.

## Что уже работает и не меняется

- Обращение открывается из бота (`/support`), кабинета и Mini App.
- Тема создаётся разбором очереди, а не в момент запроса: недоступная
  супергруппа не теряет обращение.
- Ответ из темы и ответ из админки сходятся в `_staff_reply` и оба уходят
  человеку уведомлением.
- Переписка хранится у нас, а не в Telegram: у половины плательщиков
  Telegram не привязан.

## Принятые решения

| Развилка | Решение | Почему |
|---|---|---|
| Блокировка | Две раздельные команды: `/ban` банит аккаунт, `/mute` закрывает только поддержку | Хамство в переписке и мошенничество с оплатой — разные проступки, и наказание у них разное |
| Карточка | Снимок при создании темы плюс команда `/info` за свежими данными | Правка сообщения на каждой реплике — лишний вызов Bot API и незаметное изменение старого текста |
| Устройства | Реальное число из панели, при отказе панели — «н/д» | Самый частый вопрос — «не подключается ещё одно устройство»; лимит тарифа на него не отвечает |
| Метки состояния | 🔴 ждёт нас, 🟡 ждём человека, ✅ закрыто | Цвет читается в списке тем без чтения слов |
| Язык персонала | Русский прямо в коде, без i18n | Супергруппа — рабочее место, а не интерфейс клиента; прецедент уже есть (`CLOSED_BY_STAFF`) |

## Устройство

### 1. Состояние в названии темы

Название темы собирается из метки, номера и темы обращения:

```
🔴 #12 Не подключается на телефоне
🟡 #11 Оплатил, дни не начислились
✅ #10 Как сменить тариф
```

Метка отвечает статусу обращения: `waiting_staff` → 🔴, `waiting_user` → 🟡,
`closed` → ✅. Bot API ограничивает имя темы 128 символами, поэтому имя
обрезается при сборке; хранимая тема обращения остаётся прежней, 120 символов.

Переименование стоит вызова Bot API, поэтому оно происходит только при смене
состояния, а не при каждом сообщении. Отличить одно от другого позволяет
новая колонка `tickets.topic_status_mark` — статус, который сейчас отражён в
названии. Разбор очереди сравнивает её с настоящим статусом и правит имя,
когда они разошлись.

Ответ сотрудника прямо из темы меняет статус, но в очередь ничего не кладёт:
доводить до Telegram нечего, сообщение там уже есть. Название после него
осталось бы красным. Поэтому `_staff_reply` при ответе из темы ставит в
очередь сообщение без текста — просьбу привести название в соответствие.

**Порядок в разборе очереди.** Закрытая тема Bot API переименованию не
подлежит, поэтому имя правится до закрытия:

1. Обращения нет в базе — сообщение закрывается, доводить нечего.
2. Темы нет — создать, записать номер темы, зафиксировать.
3. Отметки в названии нет — отправить карточку собеседника, проставить
   отметку, зафиксировать.
4. Есть текст — отправить его в тему.
5. Статус разошёлся с отметкой — переименовать тему, обновить отметку.
6. Просили закрыть — закрыть тему.

Шаг 3 не идемпотентен: сбой сети после доставки карточки, но до фиксации
отметки, приведёт к двум карточкам при повторе. Это выбрано осознанно —
альтернатива, отметка до отправки, теряла бы карточку совсем, а вторая
карточка в теме безобидна.

### 2. Карточка собеседника

Первое сообщение темы отвечает на вопрос «кто это и что у него куплено»:

```
👤 Иван · обращение #12
Telegram: @ivan (513442219)
Почта: ivan@example.com ✓
Тариф: Год · активна до 03.11.2026 (осталось 83 дня)
Автопродление: включено
Устройства: 3 из 5
С нами с 14.02.2026

Команды: /info /close /close_silent /mute /unmute /ban /unban
```

Собирает её отдельный модуль `services/support_card.py`, не знающий про
Telegram: он возвращает готовый текст, и его можно проверить тестом без
супергруппы.

Правила заполнения:

- Имя берётся из `users.name`; пустое — строка опускается, остаётся номер.
- Telegram: `@username (id)`; без имени пользователя — только число; без
  привязки — «не привязан».
- Почта помечается галочкой, если подтверждена; неподтверждённая — «✉ не
  подтверждена»; отсутствующей нет строки.
- Подписки нет — «Подписка: не покупал».
- Дни до конца считаются вверх: истёкшая подписка показывает «истекла
  03.08.2026 (14 дней назад)».
- Устройства запрашиваются у панели; отказ панели даёт «Устройства: н/д» и
  не мешает создать тему.
- Заблокированный или заглушённый пользователь получает строку «⛔
  Заблокирован» или «🔇 Поддержка закрыта» — иначе сотрудник не поймёт,
  почему человек молчит.

Команда `/info` присылает ту же карточку свежими данными следующим
сообщением. Старую бот не трогает: правка сообщения выше по ленте проходит
незамеченной.

### 3. Команды в теме

Право на команды даёт присутствие в супергруппе: фильтр по номеру чата уже
стоит, и отдельных ролей внутри рабочего чата не заводим.

| Команда | Действие | Ответ в теме |
|---|---|---|
| `/info` | Свежая карточка | сама карточка |
| `/close` | Закрывает обращение, человек получает уведомление | «Обращение №12 закрыто, человек уведомлён.» |
| `/close_silent` | Закрывает молча | «Обращение №12 закрыто без уведомления.» |
| `/mute` | Запрещает открывать обращения и отвечать | «Поддержка для этого человека закрыта.» |
| `/unmute` | Снимает запрет | «Поддержка снова открыта.» |
| `/ban` | Банит аккаунт и тихо закрывает обращение | «Аккаунт заблокирован, обращение №12 закрыто.» |
| `/unban` | Снимает бан | «Блокировка снята.» |

Каждая команда отвечает подтверждением: без него сотрудник не отличит
сработавшую команду от опечатки. Отказы отвечают так же — «Обращение уже
закрыто», «Нельзя заблокировать сотрудника».

Команды регистрируются до обработчика обычных сообщений, иначе их текст
уйдёт человеку как ответ поддержки — так уже сделано для `/close`.

`/ban` отказывает, если у пользователя роль `support` или `admin`: иначе
одной командой из рабочего чата гасится доступ коллеги.

Все шесть управляющих команд (кроме `/info`) пишутся в `audit_log` с
`actor_id` сотрудника: у писавшего в тему есть строка в `users`, её заводит
middleware бота. Действия: `user.ban`, `user.unban`, `user.support_mute`,
`user.support_unmute`, `ticket.close`.

### 4. Блокировка и заглушение

**Бан** ставит `users.status = banned`. Поле и проверка входа уже
существуют (`auth/service.py`), но бот сейчас пускает забаненного насквозь:
он продолжает покупать подписку и писать в поддержку. Middleware бота
начинает обрывать обработку на заблокированном, отвечая одной фразой.
Действующий короткий токен доступа в кабинете доживает свой срок — обновить
его забаненный уже не сможет.

**Заглушение** — новая колонка `users.support_muted_at`. Хранится момент, а
не флаг: при разборе жалобы важно, когда доступ закрыли. Проверка стоит в
`SupportService.open` и `reply_from_user` и даёт `ServiceError` с кодом
`support_muted`; API отвечает 403, бот — фразой «Доступ к поддержке
ограничен». Заглушённый сохраняет подписку, кабинет и оплату — закрыт
только разговор.

Заглушение не трогает уже открытые обращения: сотрудник дописывает ответ и
закрывает разговор сам. Бан закрывает обращение сразу и тихо — отвечать
заблокированному некому.

### 5. Уведомление о закрытии

Сейчас закрытие не доходит до человека никак: он видит закрытое обращение,
только когда сам откроет кабинет. Появляется вид уведомления `ticket_closed`
(служебная категория, ключ текстов `ticket.closed`, ссылка
`/account/support`, ключ дедупликации `ticket:{id}:closed`).

Уведомление уходит только при закрытии персоналом обычной командой. Тихое
закрытие, бан и закрытие самим человеком из кабинета молчат: в последнем
случае сообщать ему о его же действии незачем.

### 6. Мгновенная доставка

Сообщение ждёт разбора очереди до минуты, потому что очередь разбирается
кроном. Будить её умеют — `process_outbox.kiq()` уже вызывают роутер
вебхуков и восстановление пароля. Тот же вызов добавляется после фиксации
транзакции во всех трёх входах: бот, кабинет, админка.

Процессу бота для этого нужно клиентское подключение к брокеру TaskIQ —
в API оно открывается на время жизни приложения, в боте его пока нет. Если
подключение недоступно, вызов не должен ронять обработку сообщения:
обращение уже записано, и худшее, чего оно заслуживает, — прежнее ожидание
крона.

## Изменения в данных

Одна миграция `0019_support_workplace`:

- `tickets.topic_status_mark` — `ticket_status`, допускает пустоту. У
  существующих обращений остаётся пустой: их темы будут переименованы при
  первом же движении, а карточка придёт вдогонку.
- `users.support_muted_at` — `timestamptz`, допускает пустоту.

## Тексты

Персоналу — русский в коде рядом с обработчиками. Человеку — оба языка в
`i18n.py`: тексты `ticket.closed.{subject,body,bot}` и фразы бота о
блокировке и заглушении.

## Тестирование

- Сборка карточки: пользователь без Telegram, без почты, без подписки, с
  истёкшей подпиской, при отказе панели.
- Название темы: смена метки на каждом переходе статуса, обрезка длинного
  имени, отсутствие лишнего вызова при неизменном статусе.
- Порядок разбора очереди: переименование до закрытия, карточка один раз,
  повтор после сбоя не создаёт вторую тему.
- Команды: каждая по разу, отказ на закрытом обращении, отказ при попытке
  заблокировать сотрудника, запись в аудит.
- Заглушение: открытие и ответ отвергаются, подписка и оплата работают.
- Бан: бот обрывает обработку, вход в кабинет отвергается.
- Уведомление о закрытии: уходит при `/close`, молчит при `/close_silent`,
  при бане и при закрытии из кабинета.

Супергруппа в тестах не участвует: `SupportChat` подменяется двойником,
считающим вызовы.

## Что осознанно не делаем

- Перевод рабочего чата на второй язык.
- Роли внутри супергруппы: кто попал в чат, тот и поддержка.
- Историю блокировок отдельной таблицей — хватает `audit_log`.
- Отзыв живых сессий забаненного: короткий токен истекает сам.
- Правку уже отправленной карточки — вместо неё команда `/info`.
