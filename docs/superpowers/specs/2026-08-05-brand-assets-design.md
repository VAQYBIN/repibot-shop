Дата: 2026-08-05

Контекст: [бренд-бук](../../design/repibot-brandbook.md), [архитектура платформы](./2026-08-04-platform-architecture-design.md)

## 1. Цель

Перевести знак Re:Pibot из растра в вектор и получить полный набор файлов из §8 бренд-бука. Подпроект 1 приносит страницы входа, письма подтверждения почты и внешние ссылки на сайт — всем трём нужен знак в размерах, которых растр 150×150 не даёт.

Бренд-бук заканчивается предупреждением: «сейчас правки геометрии дешёвые, через полгода придётся переделывать восемь файлов вместо одного». Работа отвечает на него прямо — файлы не пишутся руками, а выводятся из одного описания геометрии.

**Критерий готовности:** все файлы §8 существуют, собраны генератором, совпадают с ним побайтово при повторном запуске, а веб и MiniApp не содержат ни одного растрового логотипа.

## 2. Источник

`docs/design/repibot_spiral_logo.svg` — утверждённая отрисовка: спираль из трёх полукруглых дуг с отдельным ядром, вордмарк, плашка, инверсия, фавикон и горизонтальный лок-ап на одном холсте. Геометрия чистая, без растров и масок.

Файл остаётся в репозитории как утверждённый оригинал. Генератор не читает его во время сборки — числа перенесены в код один раз и зафиксированы тестом.

### Геометрия знака

Числа переносятся из оригинала без изменений. Меняется только начало координат: холст переносится к габариту обводки.

| Параметр | Значение |
|---|---|
| Радиусы дуг | 24, 36, 48 |
| Толщина обводки | 13 |
| Радиус ядра | 8 |
| Габарит обводки | 109 × 97 |
| `viewBox` | `0 0 109 97` |
| Центр после переноса | 54.5, 42.5 |

```
M78.5 42.5 A24 24 0 0 1 30.5 42.5 A36 36 0 0 1 102.5 42.5 A48 48 0 0 1 6.5 42.5
```

Единица `x` бренд-бука — диаметр ядра, здесь 16. Обводка выходит 0.81x, зазор между ядром и ближайшим витком 9.5 = 0.59x при требуемых 0.5x. Оба инварианта проверяются арифметикой в тесте, а не глазами.

### Расхождения с бренд-буком

Оригинал рисовался раньше бренд-бука и в трёх местах с ним расходится. Везде побеждает бренд-бук: он канон, его значения уже лежат в `theme.css`, и контрасты §7 посчитаны именно для них.

| Что | В оригинале | Канон | Основание |
|---|---|---|---|
| Jade | `#1D9E75` | `#17A67C` | §2 |
| Jade Mist | `#E1F5EE` | `#E4F5EE` | §2 |
| Ink | `#0B0B0B` | `#1A1A18` | §2 |
| Скругление плашки | 0.21 стороны | 0.35 | §4 |
| Ядро на Jade-плашке | мятное, как спираль | белое | §4, «на заливке Jade ядро становится белым» |
| Знак на Ink-плашке | `#1D9E75` | Jade Bright `#2CC694` | §2, правило 4 |

Переменные `var(--text-primary)`, `var(--border)`, `var(--surface-2)` в оригинале принадлежат редактору, которым он сделан. В наших файлах их нет — цвета берутся из палитры бренд-бука либо `currentColor`.

### Правки в самом бренд-буке

Три уточнения, где описание отстало от чертежа:

1. §1 и §4 называют спираль «два витка». Дуг три, это полтора витка. Соответственно в §4 упрощённая версия — «один виток вместо полутора».
2. §4 задаёт обводку ≈0.75x, фактическая 0.81x. Правится число, не чертёж.
3. §2 правило 5 «никогда не размещать знак на зелёном фоне» противоречит §4, где выворотка на Jade разрешена. Правило относится к основной версии с Jade-ядром: на зелёном оно исчезает. Формулировка уточняется, чтобы плашка и аватар не читались как нарушение.

## 3. Архитектура

### Один источник, два генератора

```
tools/brand/geometry.py   параметры знака, палитра, композиции
tools/brand/wordmark.py   контуры «re:pibot» из Inter через fonttools
tools/brand/build.py      сборка всех SVG
tools/brand_raster.mjs    Playwright: SVG → PNG
```

Точка входа `build-brand` в `[project.scripts]`, рядом с `check`, `export-openapi` и `verify-generated`.

SVG регистрируются в `tools/verify_generated.py`. Расхождение файла с генератором роняет `uv run check` — тот же механизм, что защищает `openapi.json` и модели Remnawave.

PNG в `verify_generated` **не** регистрируются. Прогон Chromium на каждой проверке медленный, а байты рендера меняются от версии браузера — получили бы ложные срабатывания на ровном месте. Растры пересобираются отдельной командой и коммитятся как артефакты.

### Вордмарк в кривых

Самостоятельные SVG не должны зависеть от того, загрузился ли Inter. GitHub веб-шрифты в SVG не грузит вовсе, почтовые клиенты — тем более. Поэтому в файлах бренд-набора вордмарк лежит контурами.

Источник — `@fontsource-variable/inter`, файл `inter-latin-wght-normal.woff2`, уже установленный во фронтенде. `fonttools[woff]` читает woff2, инстанцирует переменную ось на wght=500 и отдаёт контуры глифов. Проверено на месте: таблицы читаются, все восемь символов `re:pibot` в подмножестве есть, `unitsPerEm` 2048.

Кернинг и трекинг −0.03em считает генератор из метрик шрифта. Просвет между знаком и вордмарком равен высоте строчной `x` (§5) — она тоже измеряется по шрифту, а не подбирается на глаз.

`fontkit` в Node пробовался первым и отпал: на этом файле у него не разбирается таблица `cmap`.

**В интерфейсе вордмарк остаётся живым текстом.** Компонент `<Wordmark>` уже существует, меняет цвет вместе с темой и переносится по строкам. Контуры нужны файлам, а не разметке.

### Растры

| Файл | Размер | Источник |
|---|---|---|

`avatar-512.png` — отдельная композиция, а не увеличенный `badge.svg`: знак выходит за края плашки, в кадре остаётся ядро и часть витков. Так требует §8.

`og-image.png` собирается на Ink `#1A1A18`: спираль `#F2F1ED`, ядро Jade Bright, вордмарк под знаком тем же светлым цветом с Jade-двоеточием.

### Упрощённый знак

Полный знак ниже 32 px нечитаем: при ширине 16 px обводка выходит 1.9 px, а зазор ядро↔виток — 1.4 px, то есть тоньше пикселя после растеризации. §4 запрещает решать это масштабированием и требует отдельную версию.

Инварианты упрощённой версии:

- два полукруга вместо трёх, то есть один виток вместо полутора;
- ядро 1.3x от полного знака;
- зазор ядро↔виток не меньше 0.5 своего `x`;
- разрыв внизу слева, как у полного знака — направление разрыва §4 называет частью узнаваемости;
- при отрисовке в 16 px обводка не тоньше 2 px, зазор не тоньше 1.5 px.

Конкретные радиусы вычисляет генератор из этих ограничений. Приёмка — отрисованное сравнение полного и упрощённого знака в 16 и 32 px: §4 прямо требует проверять глазами.

Оптическое центрирование в плашке — сдвиг вправо и вверх примерно на 0.15x (§4), тоже с визуальной проверкой.

## 5. Подключение к приложению

### Знак как компонент

`frontend/packages/ui/src/components/logo-mark.tsx` — тот же путь спирали, обводка `currentColor`, ядро `var(--rp-accent)`. Тема переключает знак сама, отдельный тёмный файл не нужен. Пропс `variant: 'full' | 'small'` выбирает геометрию.

`Lockup` в вебе перестаёт быть парой `<Image>` и собирается из `<LogoMark>` и `<Wordmark>`. MiniApp получает тот же компонент.

Путь спирали оказывается в двух местах — в генераторе и в компоненте. Тест сверяет их посимвольно: расхождение геометрии между файлами и интерфейсом — ровно то, от чего предостерегает §8.

### Что уходит

| Файл | Причина |
|---|---|
| `frontend/apps/web/public/brand/logo-{light,dark}.png` | заменяются компонентом |
| `frontend/apps/miniapp/public/brand/logo-{light,dark}.png` | то же |
| `frontend/apps/web/public/favicon.png` | заменяется `favicon.svg` + два PNG |
| `docs/design/logo-{light,dark}.png` | растровый оригинал, вектор его заменяет |
| `docs/design/lock-up-{light,dark}.png` | не используются; `lock-up-light.png` вдобавок нарушает §5 — вордмарк в нём целиком Jade |

### Что появляется

`frontend/apps/web/public/`: `favicon.svg`, `favicon-16.png`, `favicon-32.png`, `icon-192.png`, `icon-512.png`, `og-image.png`, `manifest.webmanifest`.

`frontend/apps/miniapp/public/`: `favicon.svg`. Внутри Telegram иконка вкладки не видна, но MiniApp открывается и в обычном браузере.

Манифест минимальный: имя, короткое имя, две иконки, `theme_color` Jade, `background_color` Paper, `display: standalone`. Без него `icon-192` и `icon-512` лежат мёртвым грузом — файлы из §8 без потребителя.

`layout.tsx` получает `icons` и `openGraph` в метаданных, `index.html` MiniApp — ссылку на фавикон.

Новых внешних подключений не добавляется, CSP не меняется: всё отдаётся со своего домена.

## 6. Проверки

`tools/tests/test_brand.py`:

- каждый SVG использует только цвета из палитры бренд-бука; посторонний hex роняет тест;
- путь спирали побайтово одинаков во всех файлах, где встречается, и совпадает с `logo-mark.tsx`;
- зазор ядро↔виток ≥ 0.5x — считается по параметрам для обеих версий знака;
- `logo-mark-mono.svg` не содержит ни одного hex-цвета;
- все файлы §8 существуют;
- упрощённый знак содержит ровно две дуги, полный — три;
- разрыв спирали слева: конечная точка внешней дуги левее центра.

`tools/tests/test_wordmark.py` — контуры содержат восемь глифов, двоеточие покрашено отдельно от букв.

Vitest: `LogoMark` рисует спираль и ядро и принимает оба варианта; `Lockup` не содержит ни одного `<img>`.

Растровая сборка тестами не покрывается: единственное, что можно было бы проверить, — что Chromium отработал, а это проверяет он сам ненулевым кодом возврата.

| Что | Куда | Зачем |
|---|---|---|
| `fonttools[woff]` | dev-группа Python | контуры вордмарка из woff2 |

Playwright уже стоит во фронтенде вместе с Chromium — растеризация не приносит ничего нового.

## 8. Границы

Не входит в работу:

- прелоадер из §6 (вращение спирали) — у него пока нет ни одного потребителя, появится вместе со страницами подпроекта 1;
- анимация появления через `stroke-dasharray` — по той же причине;
- печатные носители и цветовые профили CMYK;
- иконки для магазинов приложений — своего приложения у проекта нет, `icon-192` и `icon-512` нужны только PWA.
