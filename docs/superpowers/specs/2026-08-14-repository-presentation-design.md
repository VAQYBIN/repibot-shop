# Оформление репозитория

Дата: 2026-08-14
Статус: утверждён
Область: баннер README в бренд-наборе, структура README, файлы сообщества
(шаблоны issue и PR, политика безопасности, кодекс поведения), сторожа
документации.

---

## 1. Что строим

Репозиторий открытый, а выглядит как черновик: README — десять абзацев
сплошного текста без единой картинки, `.github` содержит один workflow, а
человек, пришедший сообщить об ошибке, получает пустое поле ввода.

Код при этом устроен строго: бренд выводится из одной геометрии, проверка
одна на оба языка, документацию стерегут тесты. Витрина репозитория отстала
от того, что за ней стоит.

Подпроект приводит её в соответствие. Функциональность продукта не меняется:
ни одного файла в `backend`, `frontend` или `docker` эта работа не трогает.

## 2. Принятые решения

| Решение | Выбор | Причина |
|---|---|---|
| Язык README и файлов сообщества | Русский | Проект, коммиты и документация русские, ядро аудитории Remnawave тоже. Второй файл разошёлся бы с первым к третьему релизу |
| Баннер | Собирается `build-brand` из общей геометрии | Руками написанный SVG отстанет от знака молча — от этого репозиторий уже защищён, и обходить защиту ради картинки нечестно |
| Тема баннера | Две версии, `<picture>` с `prefers-color-scheme` | Ink-полотно в светлой теме GitHub — чёрный прямоугольник посреди белой страницы |
| Слоган | Строкой markdown под баннером, не внутри SVG | `<text>` рисуется шрифтом читателя: кириллица съезжает, длина строки непредсказуема. Текст рядом ещё и индексируется |
| Растр баннера | Не делаем | GitHub отдаёт SVG в README как есть; PNG добавил бы второй файл, который надо держать в синхроне |
| Скриншоты интерфейса | Не делаем | Дизайн будет перерабатываться — снимки устареют раньше, чем их увидят |
| Подробности возможностей | Остаются в README под `<details>` | Вынос в отдельный файл прячет их за ещё одним кликом; свёрнутый блок читается там же |
| Схема архитектуры | Mermaid без своей темы | GitHub красит mermaid по теме читателя сам; жёсткие цвета сломали бы одну из двух |
| Бейджи | CI, лицензия, Python, Node, Remnawave | Пять — предел, за которым строка превращается в шум |
| Контакт для уязвимостей | Приватные Security Advisories GitHub | Почта в открытом файле уходит в спам-листы, а переписка и CVE остаются в одном месте |
| Настройки репозитория на GitHub | Не трогаем | Описание уже задано; топики и прочее — решение владельца, не задача этой работы |
| Пустые issue | Запрещены | Отчёт без версии и шагов воспроизведения дороже обходится обеим сторонам |

## 3. Баннер

### 3.1 Файлы

Два новых файла в `docs/design/logo`:

| Файл | Холст | Фон | Спираль | Ядро | Буквы | Двоеточие |
|---|---|---|---|---|---|---|
| `banner.svg` | 1280×320 | Ink `#1A1A18` | Light `#F2F1ED` | Jade Bright `#2CC694` | Light `#F2F1ED` | Jade Bright `#2CC694` |
| `banner-light.svg` | 1280×320 | Paper `#FAF9F7` | Ink `#1A1A18` | Jade `#17A67C` | Ink `#1A1A18` | Jade `#17A67C` |

Тёмная версия повторяет решение открытого графа: на Ink обычный Jade мутнеет,
поэтому берётся Jade Bright (раздел 2 бренд-бука).

### 3.2 Композиция

Внутри — горизонтальный лок-ап, тот же, что даёт `lockup_h_svg`: знак слева,
вордмарк справа, просвет между ними в высоту строчной x. Лок-ап вписан по
центру холста и занимает 34 % его высоты — остальное воздух, как того требует
раздел 5.

Функция `lockup_h_svg` сейчас выдаёт готовый SVG и не отдаёт наружу разметку с
габаритом. Баннеру нужно и то и другое, поэтому тело лок-апа выделяется в
`_lockup_h_body`, возвращающий `(разметка, ширина, высота)` — ровно так, как
уже устроен `_lockup_v_body` для вертикального лок-апа и открытого графа.
`lockup_h_svg` после этого становится обёрткой над ним, а его вывод не
меняется ни на байт: сторож сгенерированных файлов подтвердит это сам.

Ни одного нового цвета: все шесть значений уже в `PALETTE`, поэтому
параметризованный тест палитры примет новые файлы без правок.

### 3.3 Сторожа

- `tools/brand/build.py`: два элемента в `FILES`.
- `tools/verify_generated.py`: два пути в наборе `build-brand`.
- `tools/tests/test_brand.py`: цвета и наличие проверяются автоматически
  параметризацией по `FILES`; добавляется тест, что обе версии несут ту же
  спираль `FULL.path`, что и остальные файлы, и что их холст 1280×320.
- `docs/design/repibot-brandbook.md`, раздел 8: две строки в таблице файлов.

## 4. README

### 4.1 Порядок

1. **Шапка.** Баннер в `<picture>`, под ним слоган одной строкой, строка
   бейджей, строка навигации по якорям.
2. **Что это.** Четыре строки: что за продукт, поверх чего работает, для кого
   и в каком он состоянии.
3. **Возможности.** Таблица из восьми блоков: вход, подписки, панель, деньги,
   коммуникации, админка, витрина, внешний вид. Под таблицей — восемь
   `<details>`, по одному на блок, с нынешним текстом абзацев. Ни одна
   формулировка не пропадает: текст переезжает, а не сокращается.
4. **Архитектура.** Mermaid: Telegram и браузер → nginx → API, бот, воркер →
   Postgres, Redis, панель Remnawave, YooKassa.
5. **Что внутри.** Существующая таблица каталогов без изменений.
6. **Быстрый старт.** Как сейчас, включая свою главную страницу.
7. **Разработка.** Как сейчас: проверка, письмо локально, сквозные тесты.
8. **Документация.** Как сейчас, плюс ссылки на `CONTRIBUTING.md`,
   `SECURITY.md` и `CODE_OF_CONDUCT.md`.
9. **Лицензия.**

### 4.2 Бейджи

Все с `style=flat-square`, цвет акцента — Jade `17A67C`.

| Бейдж | Источник |
|---|---|
| CI | `github/actions/workflow/status` по `ci.yml`, ветка `main` |
| Лицензия | статический `AGPL--3.0` |
| Python | статический `3.13`, значение из `.python-version` |
| Node | статический `24`, значение из CI |
| Remnawave | статический `3.2.1`, ссылка на `remna.st` |

Версии проставляются руками, поэтому их ровно столько, сколько не жалко
поправить при обновлении.

### 4.3 Что сохраняется дословно

`tools/tests/test_docs.py` требует присутствия фрагментов `docker compose up`,
`uv run check`, `.env.example`, `docs/superpowers/specs` и `docs/design/logo`.
Перестановка разделов их не теряет — тесты остаются зелёными без правки.

## 5. Файлы сообщества

### 5.1 Шаблоны issue

`.github/ISSUE_TEMPLATE/bug_report.yml` — форма: где проявилось (веб, MiniApp,
бот, API, воркер, развёртывание), что произошло, шаги воспроизведения,
ожидаемое поведение, версия или коммит, вывод `docker compose logs`, отметка
«секреты из вывода вычищены». Последнее поле не формальность: `.env` проекта
содержит токен бота и ключ панели, и первый же приложенный лог утечёт их.

`.github/ISSUE_TEMPLATE/feature_request.yml` — форма: какую задачу решает, как
обходитесь сейчас, что предлагаете, готовы ли прислать PR.

`.github/ISSUE_TEMPLATE/config.yml` — `blank_issues_enabled: false` и две
ссылки: на развёртывание в документации и на приватное сообщение об
уязвимости. На Discussions не ссылаемся — они в репозитории выключены.

### 5.2 Шаблон PR

`.github/PULL_REQUEST_TEMPLATE.md`: что меняет и зачем, затем чек-лист —
`uv run check` проходит целиком, сгенерированные файлы перегенерированы,
спецификация обновлена, если менялось поведение, ветка ответвлена от `dev`.

### 5.3 Политика безопасности

`SECURITY.md`: поддерживается только `main`; сообщать через
Security → Report a vulnerability; ответ в течение недели; вознаграждения нет.
Отдельным разделом — что вне зоны ответственности проекта: настройки
развернувшего, его панель Remnawave, его ключи и его сервер. Проект отвечает
за свой код, а не за чужой `.env`.

Приватные advisory включаются владельцем в настройках репозитория одной
галочкой (Settings → Code security → Private vulnerability reporting). Это
действие на GitHub, не в коде: спецификация его фиксирует, выполняет владелец.

### 5.4 Кодекс поведения

`CODE_OF_CONDUCT.md`: Contributor Covenant 2.1 на русском. Контакт для жалоб —
приватное сообщение мейнтейнеру через GitHub; почта не публикуется.

### 5.5 CONTRIBUTING

Файл существует и переписыванию не подлежит. Добавляются две ссылки: на
кодекс поведения и на политику безопасности.

## 6. Проверка

- `uv run pytest tools/tests` — палитра, геометрия и холст баннера, сторожа
  документации.
- `uv run python tools/verify_generated.py` — баннер собран из текущей
  геометрии, а не отредактирован руками.
- Новый тест в `test_docs.py`: `SECURITY.md`, `CODE_OF_CONDUCT.md`,
  `.github/PULL_REQUEST_TEMPLATE.md` и обе формы issue существуют, а README
  ссылается на баннер.
- Глазами: README на GitHub в светлой и тёмной теме — баннер не выжигает
  страницу, mermaid читается, бейджи отвечают.
