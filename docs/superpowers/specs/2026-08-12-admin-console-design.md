# Админка: рабочее место владельца и поддержки

**Дата:** 2026-08-12
**Подпроект:** 5 «Админка и метрики» по `2026-08-04-platform-architecture-design.md`
**Область:** оболочка админки, пользователи, сводка, ноды панели

## Задача

Экраны админки существуют — платежи, обращения, рассылки, — но попасть на них
можно только набрав адрес руками: `/admin` до сих пор заглушка, а оболочка
состоит из проверки роли и фонового прямоугольника. Пользователей в админке
нет вовсе: чтобы посмотреть, что у человека с подпиской, приходится идти в
базу.

Подпроект превращает набор разрозненных страниц в рабочее место. Главный экран
в нём — карточка пользователя: половина обращений решается тем, что сотрудник
видит человека целиком и может тут же что-то поправить.

## Принятые решения

| Развилка | Решение | Почему |
|---|---|---|
| Что главное | Карточка пользователя | Ежедневная работа поддержки, а не отчётность |
| Права | Поддержке — работа с людьми, администратору — деньги | Сотрудник не должен уметь выдать себе год подписки |
| Сводка | Числа за три периода, без графиков | Один запрос, быстрая страница; динамику отложили |
| Ноды | Только просмотр | Кнопка «перезапустить» рядом со списком людей онлайн слишком легко нажимается |
| Расхождения сверки | Не в этот заход | Владелец не взял; находки продолжают копиться в базе |

## Устройство

### 1. Оболочка и права

`AdminShell` получает боковое меню и перестаёт быть пустым контейнером.
`/admin` показывает сводку вместо обещания.

Меню показывает только доступные роли разделы, а сама страница защищена
проверкой роли: `RoleGuard` получает список допустимых ролей вместо нынешнего
«любой сотрудник». Скрытая ссылка защитой не считается — каждый маршрут API
проверяет роль сам, как это уже делает `require_role`.

| Раздел | Адрес | Кто видит |
|---|---|---|
| Сводка | `/admin` | администратор |
| Пользователи | `/admin/users` | поддержка, администратор |
| Обращения | `/admin/tickets` | поддержка, администратор |
| Платежи | `/admin/payments` | администратор |
| Рассылки | `/admin/broadcasts` | администратор |
| Ноды | `/admin/nodes` | администратор |

Поддержка, открывшая `/admin`, попадает на список пользователей: сводки ей не
видно, а пустая страница вместо главной выглядела бы поломкой.

Разграничение действий внутри карточки:

| Действие | Поддержка | Администратор |
|---|---|---|
| Поиск, карточка, журнал | ✓ | ✓ |
| Блокировка, разблокировка | ✓ | ✓ |
| Заглушение поддержки | ✓ | ✓ |
| Отвязка устройства | ✓ | ✓ |
| Новая ссылка подписки | ✓ | ✓ |
| Выдать или снять дни | — | ✓ |
| Сменить тариф | — | ✓ |

### 2. Пользователи

**Список** `/admin/users`. Одна строка поиска на все опознаватели: почта,
`@username`, номер Telegram, номер аккаунта, номер в панели. Разбирает строку
сервер по трём правилам:

- строка из одних цифр ищется сразу по трём числовым полям — номеру аккаунта,
  Telegram и панели. Гадать по длине нельзя: номер в панели растёт с каждым
  заведённым пользователем и однажды сравняется по длине с чем угодно;
- строка, начинающаяся с `@`, — имя пользователя Telegram;
- всё остальное ищется вхождением по почте и имени.

Пустой запрос даёт свежих сверху: список без запроса всё равно нужен, чтобы
увидеть, кто пришёл сегодня.

Страница выдачи — двадцать строк, дальше кнопка «ещё». Смещением, а не
курсором: людей в базе тысячи, а не миллионы, и вторая страница нужна редко.

Строка списка: имя или почта, Telegram, тариф, состояние подписки с датой
окончания, отметки ⛔ и 🔇.

**Карточка** `/admin/users/[id]` из четырёх частей:

- **Кто это** — почта с отметкой подтверждения, Telegram, язык, роль,
  дата регистрации, кто пригласил.
- **Подписка** — тариф, срок, автопродление, источник, ссылка подписки,
  список устройств с отвязкой поштучно.
- **Действия** — по таблице прав выше.
- **Журнал** — начисления, платежи и решения персонала одной лентой по
  времени, свежее сверху.

Журнал собирается из трёх источников: `subscription_events` (начисления),
`orders` с попытками оплаты (деньги) и `audit_log` по этому пользователю
(решения персонала). Каждая запись несёт время, вид, описание и автора.
Собирается на сервере: три ленты, склеенные на клиенте, дали бы три запроса и
разъезжающуюся разбивку по страницам.

**Новая ссылка подписки** зовёт `/api/users/{id}/actions/revoke` панели — в
нашем фасаде такого метода пока нет. Панель меняет `shortUuid`, поэтому наш
`remnawave_subscription_url` перезаписывается ответом панели, иначе кабинет
продолжит показывать мёртвую ссылку.

### 3. Сводка

`/admin` — плитки за выбранный период: сегодня, 7 дней, 30 дней.

| Плитка | Что считает |
|---|---|
| Выручка | Сумма `orders.amount_due_rub` по заказам со статусом `fulfilled` за период |
| Оплаты | Число таких заказов |
| Новые подписки | Заказы с назначением `purchase`, ставшие `fulfilled` |
| Продления | Заказы с назначением `renew`, ставшие `fulfilled` |
| Активные подписки | Подписки в состоянии `active` на момент запроса |
| Ждут ответа | Обращения в состоянии `waiting_staff` |

Первые четыре зависят от периода, последние две — состояние на сейчас, и это
подписано на экране: иначе «активные подписки за сегодня» читается как
«появившиеся сегодня».

Считается одним запросом к нашей базе, в панель не ходит. Плитка «ждут
ответа» — ссылка на экран обращений.

Период приходит перечислением `today | week | month`, а не парой дат:
произвольный период — это выбор дат, календарь и разговор о часовых поясах,
которого сводка не стоит. Границы считаются по времени UTC, как и всё
остальное в системе.

### 4. Ноды

`/admin/nodes` — только просмотр. Панель отдаёт `GET /api/nodes`; в нашей
интеграции нод нет, поэтому появляются схема `GetNodesResponseDto` в списке
генерируемых моделей и фасад `PanelNodes` рядом с `PanelUsers`.

Показываем: имя, страну, адрес с портом, связь с панелью, включена ли,
людей онлайн, потрачено трафика из лимита, время работы Xray, последнее
сообщение о состоянии.

Молчащая панель не должна ронять страницу: экран показывает, что список
получить не удалось, и предлагает обновить.

Управление нодами — включение, перезапуск, сброс трафика — панель умеет, но
в админку не берём.

### 5. Расселение маршрутов

`routers/admin.py` — 772 строки и семь разных предметов: промокоды, тарифы,
сквады, заказы, рассылки, сегменты, обращения. Пользователи, сводка и ноды
сделают файл нечитаемым.

Файл делится по предметам на модули пакета `routers/admin/`: `catalog`
(тарифы, промокоды, сквады), `orders`, `broadcasts`, `tickets`, `users`,
`metrics`, `nodes`. Общий префикс и роутер собираются в `routers/admin/__init__.py`.

Адреса маршрутов, их подписи и ответы не меняются — это переезд, а не
переделка. Схема OpenAPI после него обязана совпасть с прежней, и это
проверяется существующей сверкой сгенерированного клиента.

## Изменения в данных

Миграций нет. Все нужные таблицы существуют; сводка и журнал читают их как
есть.

## Ошибки и отказы

- Недостаточная роль — 403 `forbidden`, как и сейчас.
- Несуществующий пользователь — 404 `not_found`.
- Отказ панели при отвязке устройства или выпуске ссылки — код
  `panel_unavailable`, который таблица отказов API уже переводит в 503. В нашу
  базу до ответа панели ничего не пишется, поэтому откатывать нечего.
- Молчащая панель на экране нод — не ошибка запроса, а пустой список с
  пометкой; страница остаётся живой.

## Тексты

Админка живёт без переводов — русский прямо в разметке, как в существующих
экранах платежей, обращений и рассылок. Правило подтверждено подпроектом 4 и
здесь не пересматривается.

## Тестирование

- Разбор строки поиска: почта, `@username`, номер Telegram, номер аккаунта,
  номер в панели, произвольная подстрока, пустая строка.
- Права: поддержка получает 403 на выдаче дней, смене тарифа, сводке и нодах;
  администратор проходит везде.
- Журнал: начисление, оплата и решение персонала попадают в одну ленту в
  правильном порядке; удалённый автор не роняет запись.
- Сводка: заказ вне периода не считается; отменённый и просроченный заказ не
  считаются; «активные подписки» не зависят от периода.
- Ноды: разбор ответа панели, молчащая панель, нода без лимита трафика.
- Новая ссылка подписки: наш адрес перезаписывается ответом панели.
- Расселение маршрутов: схема OpenAPI не изменилась.

## Что осознанно не делаем

- Экран расхождений сверки.
- Управление нодами из админки.
- Графики и выгрузку чисел в файл.
- Правку почты, пароля и роли из админки.
- Курсорную разбивку списка пользователей.
- Произвольный период в сводке.
